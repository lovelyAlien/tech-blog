# 문서 DB와 관계형 DB의 차이

데이터 중심 애플리케이션 2장에서 문서 DB와 관계형 DB를 비교한다. 두 모델이 무엇이 다르고, 다대일·다대다 관계에서는 왜 근본적으로 같다고 하는지 정리한다.

## 한눈에 비교

| | 문서 DB | 관계형 DB |
|---|---|---|
| 저장 단위 | JSON 같은 문서 하나 | 테이블의 행 |
| 일대다 표현 | 자식을 부모 문서 안에 중첩 | 별도 테이블 + 외래 키 |
| 스키마 | 읽을 때 해석(schema-on-read) | 쓸 때 검증(schema-on-write) |
| 지역성 | 좋음(문서를 통째로 읽음) | 떨어짐(여러 테이블에 흩어짐) |
| 다대일·다대다 | 문서 참조 + 읽을 때 추가 쿼리 | 외래 키 + JOIN |

- 문서 DB는 일대다 트리 구조(이력서, 글과 댓글)에 잘 맞고, 스키마를 자주 바꿔야 할 때 유연하다.
- 관계형 DB는 다대다 관계가 많고 정합성이 중요할 때 유리하다.
- 요즘은 관계형 DB도 JSON 컬럼을 지원하고, 문서 DB도 JOIN 유사 기능과 트랜잭션을 지원해서 경계가 흐려지고 있다.

## 다대일·다대다는 근본적으로 같다

공유되는 데이터는 복사하지 않고 **고유 ID로 참조**한다. 관계형은 이를 **외래 키**, 문서 모델은 **문서 참조**라고 부른다.

```
// 관계형: users.company_id → companies.id (외래 키)
users:     | 1 | 철수 | company_id=7 |
companies: | 7 | A사  |

// 문서 DB: 문서 참조
{"_id": 1, "name": "철수", "company_id": 7}
{"_id": 7, "name": "A사"}
```

- 회사 정보는 한 곳에만 있으므로 회사명이 바뀌어도 한 곳만 고치면 된다.
- 차이는 저장 방식이 아니라 **읽을 때 참조를 따라가는 방법**이다. 관계형은 DB가 JOIN으로 처리하고, 문서 DB는 보통 추가 쿼리가 필요하다.
- 문서 DB가 다대다에 약하다는 말은 참조를 표현하지 못해서가 아니라 JOIN 지원이 약하기 때문이다.

## 한 줄 정리

> 문서 DB는 "묶어서 저장해 한 번에 읽기", 관계형 DB는 "쪼개서 저장하고 JOIN으로 합치기"이며, 다대일·다대다는 두 모델 모두 고유 ID 참조라는 같은 방식이다.
