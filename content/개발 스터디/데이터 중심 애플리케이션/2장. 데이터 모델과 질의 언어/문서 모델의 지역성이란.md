# 문서 모델의 지역성이란

데이터 중심 애플리케이션 2장에 "NoSQL은 다중 테이블 스키마보다 더 나은 지역성을 갖는다"는 말이 나온다. 지역성이 무엇인지, NoSQL이 언제 유리한지 정리한다.

## 핵심

- **다중 테이블 스키마:** 한 사람의 이력서를 `users`, `positions`, `education` 같은 여러 테이블로 쪼개 저장한다. 조회하려면 JOIN이 필요하다.
- **지역성(locality):** 관련 데이터가 한 곳에 붙어 있는 정도다.
- **문서 모델:** 이력서 한 장을 JSON 하나로 저장하므로, 한 번 읽으면 필요한 정보가 모두 나온다.

```json
{
  "user_id": 251,
  "name": "철수",
  "positions": [{"job_title": "개발자", "company": "A사"}],
  "education": [{"school": "C대학"}]
}
```

| | 문서 모델 | 관계형 |
|---|---|---|
| 이력서 한 장 조회 | 문서 1번 읽기 | 여러 테이블 JOIN |

## NoSQL이 유리한 경우

- 데이터가 문서 단위로 통째로 읽힌다.
- 스키마가 자주 바뀌거나 레코드마다 구조가 다르다.
- 일대다 트리 구조 데이터다(이력서, 주문서와 항목, 글과 댓글).
- 수평 확장이 중요하다.

## 관계형이 유리한 경우

- 다대다 관계가 많다.
- 여러 데이터 간 정합성이 중요하다.
- 문서의 일부만 필요해도 문서 전체를 읽어야 하는 것이 문서 모델의 단점이다.

## 한 줄 정리

> 지역성은 관련 데이터가 한 곳에 모여 있다는 뜻이고, 문서 모델은 이 덕분에 트리 구조 데이터를 쿼리 한 번으로 읽는다.
