# 관계형 모델은 무엇을 숨기는가

데이터 중심 애플리케이션 2장에서 "관계형 모델의 목표는 정리된 인터페이스 뒤로 구현 세부 사항을 숨기는 것"이라고 한다. 이 문장이 무슨 뜻인지 정리한다.

## 핵심

- **정리된 인터페이스:** 개발자는 테이블, 행, 열만 본다.
- **숨겨진 구현 세부 사항:** 디스크 저장 방식, 인덱스 사용 여부, JOIN 순서, 캐시 등.
- 개발자는 **무엇을 원하는지**만 말하고, **어떻게 찾을지**는 DB(쿼리 최적화기)가 정한다. 이를 선언형이라고 한다.

## 이전 방식과 비교

| | 관계형 모델 | 이전 방식(계층·네트워크 모델) |
|---|---|---|
| 개발자가 하는 일 | 원하는 결과를 선언 | 포인터를 따라 경로를 직접 탐색 |
| 경로 결정 | DB | 개발자 |
| 저장 방식이 바뀌면 | 쿼리 그대로 | 코드 수정 필요 |

```sql
SELECT * FROM users WHERE email = 'a@b.com';
```

인덱스를 추가해도 이 쿼리는 고칠 필요가 없다.

## 한 줄 정리

> 관계형 모델은 "표"라는 단순한 모양만 노출하고 저장·탐색 방법은 DB 안에 숨겨서, 구현이 바뀌어도 애플리케이션이 영향받지 않게 한다.
