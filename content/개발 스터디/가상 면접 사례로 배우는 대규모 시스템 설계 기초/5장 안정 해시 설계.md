## 해시 키 재배치 문제
대규모 시스템에서 데이터를 여러 서버에 분산 저장할 때  
가장 먼저 떠올리는 방법은 **해시 함수**를 이용한 분산이다.

하지만 단순한 해시 기반 분산 방식은  
서버가 추가되거나 제거되는 순간 **치명적인 재배치 문제**를 일으킨다.

일반적인 해시 기반 분산 방식
```text
	serverIndex = hash(key) % numberOfServers
```
이 방식은 다음 조건에서는 잘 동작한다.

- 서버 풀(server pool)의 크기가 고정되어 있고
    
- 키의 분포가 균등할 때
    

하지만 현실의 대규모 시스템에서는  
**서버 풀의 크기가 고정되지 않는다.**

- 서버 증설 (Scale-out)
    
- 장애로 인한 서버 제거
    
- 오토스케일링
    

이때 문제가 발생한다.

---

### 왜 문제가 되는가?

서버 수가 변경되면:

- `hash(key)` 값은 동일하지만
    
- `% numberOfServers` 결과가 달라진다
    

즉, **대부분의 키가 다른 서버로 매핑**된다.

#### 예시

|키|hash(key)|서버 수 = 4|서버 수 = 5|
|---|---|---|---|
|A|17|1|2|
|B|23|3|3|
|C|9|1|4|

서버가 하나만 늘어났을 뿐인데  
👉 **대부분의 키가 재배치**된다.

---

### 재배치가 왜 위험한가?

- 캐시 시스템  
    → 캐시 미스 폭증(Cache Stampede)
    
- 데이터 저장 시스템  
    → 대량 데이터 이동
    
- 트래픽 급증  
    → 네트워크·스토리지 부하
    

즉, **확장성과 가용성을 위해 서버를 늘렸는데 오히려 장애를 유발**할 수 있다.

이 문제를 해결하기 위해 등장한 개념이 바로 **안정 해시(Consistent Hashing)** 다.

---

## 안정 해시(Consistent Hashing)

안정 해시는  
**서버 수가 변경되더라도 재배치되는 키의 수를 최소화**하기 위한 해시 기법이다.

### 핵심 아이디어

> 서버와 키를 **같은 해시 공간(원형 링)** 위에 배치한다.

- 해시 공간은 0 ~ 2³²-1 같은 원형 구조
    
- 서버도 해시 값으로 링 위에 배치
    
- 키도 해시 값으로 링 위에 배치
    
- 키는 **시계 방향으로 가장 가까운 서버**에 저장된다

---

### 안정 해시의 장점

- 서버 추가 시  
    → **일부 키만 새로운 서버로 이동**
    
- 서버 제거 시  
    → 해당 서버가 담당하던 키만 재배치
    
- 전체 키 재배치 ❌
    

즉, 서버 수 변경 시  
👉 **O(1/N) 수준의 키만 이동**

---

### 하지만 안정 해시에도 문제가 있다

#### 문제 1. 데이터 불균형

- 서버 해시 값이 고르지 않으면
    
- 특정 서버에 키가 몰릴 수 있다
    

#### 문제 2. 서버 수가 적을수록 불리

- 서버 개수가 적으면
    
- 해시 링에서 간격이 넓어져 불균형 심화
    

이 문제를 해결하기 위해 등장한 개념이 **가상 노드(Virtual Node)** 다.

---

## 가상 노드(Virtual Node)

가상 노드는  
**하나의 물리 서버를 여러 개의 논리적 노드로 쪼개어 해시 링에 배치**하는 방식이다.

### 동작 방식

- 하나의 물리 서버 → 여러 개의 가상 노드
    
- 각 가상 노드는 서로 다른 해시 값을 가짐
    
- 키는 가장 가까운 **가상 노드**에 매핑
    
- 가상 노드가 속한 물리 서버가 실제 저장 담당

![[5장 안정 해시 설계-20260202-210851.png]]

---

### 가상 노드의 효과

#### 1️⃣ 데이터 분포 균등화

- 서버가 해시 링 전반에 고르게 분포
    
- 핫스팟 완화
    

#### 2️⃣ 서버 추가/제거 시 영향 최소화

- 물리 서버 하나 추가
    
- → 가상 노드 몇 개만 링에 추가
    
- → 이동되는 키의 양 예측 가능
    

#### 3️⃣ 서버 성능 차이 반영 가능

- 성능 좋은 서버 → 가상 노드 더 많이
    
- 성능 낮은 서버 → 가상 노드 적게
    

---

### 가상 노드 예시

`Server A → A1, A2, A3 Server B → B1, B2, B3 Server C → C1, C2, C3`

이렇게 구성하면:

- 키는 A/B/C 중 하나가 아니라
    
- A1, B2, C3 같은 **가상 노드 단위로 분산**
    

결과적으로 **훨씬 균등한 분산**이 가능해진다.

---

## 정리

### 일반 해시 방식의 문제

- 서버 수 변경 시 대부분의 키 재배치
    
- 확장성, 가용성에 치명적
    

### 안정 해시의 핵심

- 서버와 키를 동일한 해시 링에 배치
    
- 서버 변경 시 최소한의 키만 이동
    

### 가상 노드의 역할

- 데이터 불균형 문제 해결
    
- 확장성과 예측 가능성 강화
