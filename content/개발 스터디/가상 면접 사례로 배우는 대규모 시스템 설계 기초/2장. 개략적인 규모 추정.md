## 제프 딘(Jeff Dean)이 정리한 컴퓨터 연산 지연 시간 분석 핵심

구글의 제프 딘은 컴퓨터 시스템에서 발생하는 **연산 및 I/O 지연 시간(latency)**을 수치로 분석하며,  
대규모 시스템 설계 시 반드시 고려해야 할 몇 가지 중요한 결론을 제시했다.

### 1. 메모리는 빠르지만, 디스크는 여전히 느리다

- 메모리 접근은 **나노초(ns)** 단위
    
- 디스크 접근은 **마이크로초(µs) ~ 밀리초(ms)** 단위  
    → 수천~수백만 배의 차이가 발생한다.
    

👉 **가능한 한 데이터를 메모리에 유지하는 설계가 중요하다.**

---

### 2. 디스크 탐색(Seek)은 가능한 한 피하라

- 디스크는 연속 읽기보다 **랜덤 탐색 비용이 매우 크다**
    
- 디스크 seek 한 번은 수많은 CPU 연산보다 비싸다
    

👉 **랜덤 I/O를 줄이고, 순차 접근 또는 캐시 활용이 핵심이다.**

---

### 3. 단순한 압축 알고리즘은 매우 빠르다

- 압축/해제 연산은 CPU 기준으로 매우 저렴한 비용
    
- 반면 디스크 및 네트워크 I/O는 상대적으로 매우 느림
    

👉 **CPU를 조금 더 사용하더라도, I/O를 줄이는 편이 전체 성능에 유리하다.**

---

### 4. 데이터를 네트워크로 전송하기 전, 가능하면 압축하라

- 네트워크 전송 비용은 압축 비용보다 훨씬 크다
    
- 특히 데이터 크기가 클수록 효과가 커진다
    

👉 **“압축 → 전송 → 해제”가 “그냥 전송”보다 빠른 경우가 많다.**

---

### 5. 데이터 센터 간 통신은 생각보다 오래 걸린다

- 대규모 서비스는 여러 지역의 데이터 센터에 분산되어 있음
    
- 데이터 센터 간 네트워크 왕복 시간은 무시할 수 없음
    

👉 **지역 간 동기 통신을 최소화하고, 비동기·로컬 처리 위주의 설계가 필요하다.**
