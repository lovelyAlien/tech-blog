# 캐시 무효화 신호를 Kafka가 아니라 Redis Pub/Sub으로 보내는 이유

메시지는 Kafka로 보내면서 캐시 지우기 신호는 왜 Redis Pub/Sub으로 보냈냐는 질문이 자주 나온다. 핵심은 **데이터 성격이 다르면 도구도 나눠 쓴다**는 것이다. 메시지는 유실되면 안 되는 데이터이고, 무효화 신호는 놓쳐도 다른 장치로 보완할 수 있는 작은 신호다.

## 상황: 서버마다 따로 있는 로컬 캐시

SenCloud에서는 Talk 서버(Pod 여러 대)가 채널 참여자 목록을 각자 메모리(Caffeine 로컬 캐시)에 들고 있었다. 참여자는 메시지를 보낼 때마다 읽지만, 입장·퇴장·강퇴 때만 바뀐다.

```
[멤버 변경]  DB 커밋 → 내 서버 캐시 삭제
                    → Redis Pub/Sub으로 채널 ID만 전파 (목록은 안 보냄)
                    → 다른 Talk 서버들도 각자 삭제 → 다음 조회 때 DB에서 다시 불러옴
```

그래서 필요한 건 "채널 123 캐시 지워라"라는 **작은 신호를 모든 서버에 뿌리는 것**이다.

## Kafka로 했다면

Kafka는 같은 컨슈머 그룹 안에서 메시지를 **나눠 갖는** 구조다. 모든 서버가 같은 신호를 받으려면 서버마다 컨슈머 그룹을 따로 둬야 한다.

- Pod가 재배포·스케일링될 때마다 그룹 ID가 바뀌면, 쓰지 않는 그룹이 계속 쌓인다.
- Kafka의 장점인 "보관했다가 다시 읽기"도 여기선 이득이 작다. 재시작한 서버는 **빈 캐시로 시작**하니까 지난 무효화 신호를 다시 읽을 이유가 없다.

## Redis Pub/Sub의 약점과 보완

Pub/Sub은 구독만 하면 모든 서버가 받는다. 대신 **메시지를 보관하지 않는다.** 구독이 끊긴 사이에 보낸 신호는 그냥 사라진다.

| 놓치는 경우 | 보완 |
|---|---|
| 구독 연결이 끊겼다 붙음 | 재구독 시 캐시를 **통째로 삭제** |
| 연결은 살아 있는데 신호 하나만 빠짐 | **만료 시간(24시간)** 이 마지막 안전망 |

마지막 경우는 만료 시간까지 옛 목록이 남을 수 있다. 면접에서는 이걸 한계로 인정하는 게 낫다.

## 비교

| | Redis Pub/Sub (채택) | Kafka |
|---|---|---|
| 모든 서버에 전달 | 구독만 하면 됨 | 서버마다 컨슈머 그룹 필요, Pod 바뀌면 그룹이 쌓임 |
| 유실 | 보관 안 함 → 재연결 시 전체 삭제 + 만료 시간으로 보완 | 보관했다가 다시 읽을 수 있음 |
| 재시작한 서버 | 빈 캐시라 지난 신호 불필요 | 보관 기능의 이득이 작음 |
| 맞는 데이터 | 작고, 놓쳐도 보완 가능한 신호 | 유실되면 안 되는 메시지·이벤트 |

## 말하기 대본

> 메시지 자체는 Kafka로 보냈고, 참여자 캐시를 지우라는 신호는 Redis Pub/Sub으로 보냈습니다. 데이터 성격이 달라서 나눴습니다.
> 지우기 신호는 채널 ID 하나만 담은 작은 신호이고, 모든 Talk 서버가 받아야 합니다. Pub/Sub은 구독만 해 두면 모두 받습니다. Kafka로 하려면 서버마다 컨슈머 그룹을 따로 둬야 하고, Pod가 바뀔 때마다 그룹이 쌓입니다.
> Pub/Sub은 보관하지 않아 신호를 놓칠 수 있어서, 재연결되면 캐시를 전부 지우고 24시간 만료 시간을 안전망으로 뒀습니다. 재시작한 서버는 빈 캐시로 시작하니 지난 신호를 다시 읽을 필요가 없어서, Kafka의 보관 기능은 여기서 얻는 게 적다고 판단했습니다.

꼬리 질문 "신호를 놓친 서버는 옛 목록으로 보내지 않나요?" → 재연결은 전체 삭제로 막고, 연결 중 하나만 빠지는 경우는 만료 시간까지 어긋날 수 있다고 한계로 인정한다.

> 주의: Pub/Sub과 무효화를 쓴 건 실제 구조지만, Kafka와 비교해서 골랐다는 과정은 나중에 재구성한 근거다. "비교해서 골랐다"고 단정하지 말고 "이런 이유로 Pub/Sub이 맞다고 판단합니다"로 말한다.

## 한 줄 정리
> 유실되면 안 되는 메시지는 Kafka, 모든 서버에 뿌리는 작은 무효화 신호는 Pub/Sub. 유실은 재연결 시 전체 삭제 + 만료 시간으로 보완한다.
