**① GET 로그인 요청**  
브라우저가 "카카오 로그인" 버튼을 누르면 백엔드의 로그인 시작 엔드포인트(Spring Security 기본값 기준 `/oauth2/authorization/kakao`)로 GET 요청을 보내요. 이 요청엔 특별한 파라미터가 없고, 그냥 "카카오 로그인 흐름을 시작해줘"라는 신호예요.

**② 302 (카카오 인증 URL)**  
백엔드가 `application.yml`에 등록해둔 `client-id`, `redirect-uri`, `scope` 등을 조합해서 카카오 인증 URL을 만들어요. 이때 `state` 값(랜덤 문자열)도 같이 생성해서 서버 세션에 저장해두는데, 이건 나중에 ⑥에서 돌아온 값이 진짜 우리가 보낸 요청에 대한 응답인지 검증하기 위한 CSRF 방지 장치예요. 만든 URL을 `Location` 헤더에 담아 302 응답.

**③ GET /oauth/authorize**  
브라우저가 ②의 `Location`을 보고 자동으로 그 주소로 이동해요. 이건 브라우저의 기본 동작이라 어떤 코드 개입도 없어요. 이 요청엔 `client_id`, `redirect_uri`, `response_type=code`, `state` 등이 쿼리파라미터로 붙어 있고, 백엔드는 이 통신에 전혀 끼지 않아요.

**④ 로그인/동의 화면 응답**  
카카오 인증 서버가 요청을 받고, 사용자가 카카오 계정에 이미 로그인돼 있는지 확인해요. 안 돼 있으면 로그인 폼을, 돼 있으면 동의 화면을(이미 동의한 적 있으면 ⑤⑥을 건너뛰고 곧바로 리다이렉트하기도 해요) 응답해요. 이 화면은 카카오가 직접 서빙하는 페이지라 우리 서비스 UI와는 무관해요.

**⑤ POST 로그인 제출**  
사용자가 아이디/비번을 입력하고 동의 버튼을 누르면, 브라우저가 그 폼 데이터를 카카오 서버로 POST해요. 여기서 중요한 포인트는, 사용자의 카카오 비밀번호가 우리 백엔드를 절대 거치지 않는다는 것 — 이게 OAuth를 쓰는 핵심 이유 중 하나예요.

**⑥ 302 (code + 콜백 URL)**  
카카오가 로그인/동의 검증을 마치면, 맨 처음 등록해둔 `redirect_uri`로 302 응답을 보내요. 이때 쿼리파라미터에 `code`(인가 코드)와 `state`(②에서 보낸 값 그대로)가 붙어 있어요. `code`는 보통 수명이 몇 분 정도인 1회용 값이에요.

**⑦ GET 콜백 (code 전달)**  
브라우저가 ⑥의 `Location`으로 다시 자동 이동하는데, 이번엔 그 주소가 우리 백엔드의 콜백 엔드포인트(`/login/oauth2/code/kakao`)라서 백엔드가 다시 등장해요. 백엔드는 이때 받은 `state`가 ②에서 세션에 저장해둔 값과 일치하는지부터 검증해요.

**⑧ POST /oauth/token (code)**  
여기가 백엔드가 카카오 서버에 직접 보내는 첫 서버-서버 요청이에요. `code`, `client_id`, `client_secret`, `redirect_uri`, `grant_type=authorization_code`를 담아 전송하는데, `client_secret`이 들어가기 때문에 반드시 서버에서만 호출 가능하고 프론트엔드/앱에는 절대 노출되면 안 돼요.

**⑨ access_token 발급**  
카카오가 `code`의 유효성을 검증하고 `access_token`(과 보통 `refresh_token`)을 응답해요. 이 시점부터 우리 서버는 이 사용자를 대신해 카카오 API를 호출할 권한을 갖게 돼요.

**⑩ GET /v2/user/me (Bearer)**  
받은 `access_token`을 `Authorization: Bearer` 헤더에 담아 카카오 API 서버에 사용자 정보를 요청해요.

**⑪ 사용자 정보 응답**  
카카오가 `id`, `nickname`, `email`(동의받은 scope에 한해서) 등을 JSON으로 응답해요.

**⑫ 로그인 완료 (자체 JWT)**  
백엔드가 ⑪에서 받은 정보로 자체 회원 DB를 조회하고, 없으면 가입 처리한 뒤, 우리 서비스 전용 JWT(또는 세션)를 발급해서 클라이언트에 응답해요. 이후 클라이언트는 카카오가 아니라 이 JWT로 우리 서비스의 다른 API를 호출하게 됩니다.

## 엑세스 코드가 필요한 이유
만약 access_token을 바로 줘버리면
```
카카오 → 브라우저: 302 Redirect
Location: https://ourapp.com/callback#access_token=AbC123...
```
이 URL 자체가 위험:
- **브라우저 히스토리**에 그대로 남음 (PC방, 공용기기에서 위험)
- 누군가 이 URL 하나만 가로채면 **그 즉시 그 사람으로 카카오 API 호출 가능** — 추가 인증 단계가 전혀 없음

**반면 인가 코드(code)를 줄 때는**, 코드 자체가 노출되더라도 공격자가 곧바로 못 써요. 이유는:
1. **수명이 짧음** (보통 몇 분, 1회용) — 가로챈다 해도 시간 지나면 무효
2. ⑧번 교환 과정에서 카카오가 **"이 요청이 정말 등록된 우리 서버에서 온 게 맞는지"**(client_id + secret 조합)까지 같이 검증함 — code만 가지고는 이 신원 증명이 안 됨
