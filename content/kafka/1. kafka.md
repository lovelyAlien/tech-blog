카프카란?
- 분산 스트리밍 플랫폼으로, 대규모 실시간 데이터 스트리밍 처리를 위해 설계
- 이벤트 기반 아키텍처를 사용하여 대량의 데이터를 처리하고, 여러 시스템 간 데이터 통신을 지원
- pub/sub 모델을 기반으로 만들어진 메세징 시스템

메시징 시스템
로그 데이터, 이벤트 메시지 등 API 로 호출할 때 보내는 데이터들을 처리하는 시스템

pub/sub 모델이란
중앙에 메시징 시스템 서버를 두고, 메시지를 보내고(publish), 받는(subscribe) 형태의 통신
N:M으로 연결되는 것이 아니기 때문에 확장성이 용이

디스크에 메시지 저장
(기존 메시징 시스템 - RabbitMQ, ActiveMQ)
- 컨슈머가 메시지 읽어가면 큐에서 바로 삭제
(카프카): 보관 주기 동안 디스크에 메시지 저장
- 트래픽이 폭주해 컨슈머의 처리가 늦어져도 카프카 디스크에 안전하게 보관 됨 -> 메시지 손실x

디스크 I/O 는 느리지 않을까?
아니다! 카프카는 **페이지 캐시**를 이용해서 디스크 접근을 최소화 시켜, 처리 속도가 빠름

페이지 캐시
OS에서 사용하는 페이지 캐시와 동일

카프카 구성 요소
카프카는 분산 아키텍처로 구성되어 있으며, 여러 브로커가 클러스터를 형성하여 데이터를 저장하고 관리한다. 각 브로커는 토픽을 파티션으로 나누어 저장하며, 클러스터 내에서 데이터 복제를 통해 고가용성을 유지한다.

- 브로커: 카프카 서버의 노드. 프로듀서로부터 메시지를 받아 저장하고 컨슈머에 메시지 전달
- 토픽: 메시지의 분류를 위한 일종의 카테고리
- 프로듀서: 메시지를 토픽에 발행하는 어플리케이션
- 컨슈머: 토픽에서 메시지 읽어오는 어플리케이션
- 파티션: 토픽은 여러 파티션으로 나눈 단위. 데이터의 병렬 처리와 확장성을 가능하게 함
