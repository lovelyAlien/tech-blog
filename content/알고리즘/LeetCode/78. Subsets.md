# Subsets: 결정 트리를 DFS로 도는 백트래킹 기본형

모든 부분집합을 나열하는 문제다. 백트래킹의 "선택 → 탐색 → 되돌리기" 뼈대를 익히는 가장 기본 문제이고, `List.remove(int)` 오버로딩과 "복사 없이 저장"이라는 Java 백트래킹의 대표 함정 두 개를 한 번에 밟아서 정리해 둔다.

- 문제: [LeetCode 78. Subsets](https://leetcode.com/problems/subsets/)

## 문제 요약

- 서로 다른 정수 배열 `nums`의 **모든 부분집합**(power set)을 반환한다. 순서는 상관없고 중복은 안 된다.
- `1 <= nums.length <= 10`, `-10 <= nums[i] <= 10` ← **음수가 들어온다**

```
Input:  nums = [1,2,3]
Output: [[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]
```

## 접근: 원소마다 "넣는다 / 안 넣는다"

원소 하나마다 선택지가 2개(넣기/안 넣기)이므로 부분집합은 2ⁿ개다. 이 선택 과정을 그리면 **결정 트리**가 된다.

```
                    []
           /                 \
        +1                    X
       [1]                    []
      /    \                /    \
    +2      X             +2      X
  [1,2]    [1]            [2]     []
  /  \     /  \          /  \    /  \
[1,2,3][1,2][1,3][1]  [2,3][2]  [3]  []    ← 리프 8개 = 답
```

- 이 트리는 코드에 자료구조로 존재하지 않는다. **선택 과정을 그려 보면 트리 모양이 된다**는 뜻이다.
- 이 트리를 재귀로 **한 길씩 끝까지 내려갔다가 되돌아오며(DFS)** 훑는 것이 백트래킹이다.
- 경로 리스트 하나(`arr`)를 add/remove로 재사용하므로 메모리는 트리 깊이 O(n)만 든다. BFS로 돌면 한 층의 부분 결과를 전부 들고 있어야 한다.

## 제출한 풀이 (버그 있음)

처음 제출한 코드다. "넣기 → 재귀 → 빼기 → 안 넣고 재귀"라는 트리 구조는 맞았지만 두 줄이 틀렸다.

```java
class Solution {
    List<List<Integer>> answer = new ArrayList<>();

    private void backtrack(int [] nums, int depth, List<Integer> arr) {
        if(depth == nums.length) {
            answer.add(arr);                 // ❌ ② 복사 없이 참조를 저장
            return;
        }

        arr.add(nums[depth]);
        backtrack(nums, depth+1, arr);
        arr.remove(nums[depth]);             // ❌ ① 값이 아니라 "인덱스"로 삭제됨
        backtrack(nums, depth+1, arr);
    }
    public List<List<Integer>> subsets(int[] nums) {
        backtrack(nums, 0, new ArrayList<>());
        return answer;
    }
}
```

## 수정한 풀이 (넣기/안 넣기 이진 결정 트리)

```java
class Solution {
    List<List<Integer>> answer = new ArrayList<>();

    private void backtrack(int [] nums, int depth, List<Integer> arr) {
        if(depth == nums.length) {
            answer.add(new ArrayList<>(arr));    // 저장 시점의 스냅샷을 복사
            return;
        }

        arr.add(nums[depth]);                    // 가지 1: 넣는다
        backtrack(nums, depth+1, arr);
        arr.remove(arr.size() - 1);              // 되돌리기: 방금 넣은 마지막 원소 삭제
        backtrack(nums, depth+1, arr);           // 가지 2: 안 넣는다 (add가 없으니 remove도 없음)
    }
    public List<List<Integer>> subsets(int[] nums) {
        backtrack(nums, 0, new ArrayList<>());
        return answer;
    }
}
```

선택지가 "넣기/안 넣기" 2개로 고정이라, for문을 **손으로 풀어 쓴 형태**다. 굳이 for문으로 쓰면 `for (boolean take : new boolean[]{true, false})` 안에 `if (take)`가 두 번 들어가 오히려 읽기 어렵다.

## 다른 구현: for문 방식 ("다음에 넣을 원소 고르기")

층마다 묻는 질문을 바꾼다.
- 위 풀이: "**nums[depth]를** 넣을까 말까?" → 가지 2개 고정
- 이 풀이: "**다음으로 넣을 원소**는 뭘로 할까? (방금 넣은 것보다 뒤에서)" → 가지 개수가 매번 달라서 for문이 필요하다

```java
class Solution {
    List<List<Integer>> answer = new ArrayList<>();

    private void backtrack(int[] nums, int start, List<Integer> arr) {
        answer.add(new ArrayList<>(arr));            // 모든 노드가 곧 답 (종료 조건 없음)

        for (int i = start; i < nums.length; i++) {  // 다음 원소 후보: start부터 끝까지
            arr.add(nums[i]);
            backtrack(nums, i + 1, arr);             // i 뒤쪽만 보게 해서 [1,2]/[2,1] 중복 방지
            arr.remove(arr.size() - 1);
        }
    }
    public List<List<Integer>> subsets(int[] nums) {
        backtrack(nums, 0, new ArrayList<>());
        return answer;
    }
}
```

```
              []
      /        |       \
    [1]       [2]      [3]
   /   \       |
[1,2] [1,3]  [2,3]
  |
[1,2,3]                 ← 노드 8개가 모두 답
```

| | 넣기/안 넣기 (제출) | 다음 원소 고르기 (for문) |
|---|---|---|
| 층이 묻는 것 | "nums[depth]를 넣을까?" | "다음엔 뭘 넣을까?" |
| 가지 수 | 항상 2 | `n - start`개 |
| 답을 저장하는 곳 | **리프만** (`depth == n`) | **모든 노드** (함수에 들어오자마자) |
| 종료 조건 | `depth == n`이면 return | 없음. `start == n`이면 for문이 안 돌아서 끝남 |
| 전체 노드 수 | 2ⁿ⁺¹ - 1 | 2ⁿ (버리는 노드 없음) |

for문 방식이 중요한 이유는 **다른 백트래킹 문제에 그대로 쓰이는 템플릿**이기 때문이다.

| 문제 | for문 방식에서 바꿀 부분 |
|---|---|
| #77 Combinations | `arr.size() == k`일 때만 저장 |
| #39 Combination Sum | 재귀에 `i + 1` 대신 `i` (재사용) + 합이 넘으면 `break` |
| #46 Permutations | `start` 대신 0부터 돌고 `used[]`로 거르기 |

## 핵심 포인트

- **백트래킹 = 결정 트리를 DFS로 도는 것.** 한 칸 내려가기는 `add` + 재귀 호출, 한 칸 올라오기는 재귀 return + `remove`다.
- **add와 remove는 항상 짝이다.** 되돌렸기 때문에 다음 가지를 깨끗한 상태에서 시작할 수 있다. 안 넣는 가지는 add가 없으니 remove도 없다.
- 복잡도: 부분집합 2ⁿ개 × 각각 복사 O(n) = **시간 O(n · 2ⁿ)**. 공간은 재귀 깊이와 `arr` 길이 O(n) (결과 리스트 제외).

## 주의할 점 / 흔한 실수

**① `arr.remove(nums[depth])`: 인덱스로 삭제된다**

`List<Integer>`에는 `remove(int index)`와 `remove(Object o)`가 있다. `nums[depth]`는 `int`이므로 Java는 박싱이 필요 없는 **`remove(int index)`를 먼저 고른다.** "값 3을 지워라"가 아니라 "3번 인덱스를 지워라"가 된다.

```
[1,2,3]에서: add 1 → add 2 → add 3 → [1,2,3] 저장 후 return
arr.remove(nums[2]) = remove(3) → 크기 3인 리스트의 인덱스 3 → 💥 IndexOutOfBoundsException
```

음수(`-10 <= nums[i]`)가 들어오면 `remove(-1)`로 바로 터진다.
→ 방금 넣은 건 항상 마지막 원소이므로 **`arr.remove(arr.size() - 1)`**로 지운다. `remove(Integer.valueOf(x))`도 돌아가긴 하지만 O(n) 탐색이고, 중복 원소가 있으면 엉뚱한 걸 지울 수 있다.

**② `answer.add(arr)`: 복사 없이 저장하면 전부 빈 리스트가 된다**

`arr`는 모든 재귀가 같이 쓰는 **리스트 하나**다. `answer`에는 그 리스트의 참조가 8번 들어가고, 탐색이 끝나면 remove로 다 비워져서 결과가 `[[],[],[],[],[],[],[],[]]`가 된다.

```
answer ─┬─→ ┐
        ├─→ ├─→  arr (하나뿐, 마지막엔 [])
        └─→ ┘
```

→ **`answer.add(new ArrayList<>(arr))`**로 저장하는 순간의 스냅샷을 복사한다.

**③ (참고) `answer`를 필드로 두기**

LeetCode는 테스트마다 `Solution`을 새로 만들어서 통과한다. 하지만 같은 객체로 `subsets()`를 두 번 부르면 결과가 누적된다. 라이브 코딩에서는 메서드 안의 지역 변수로 만들어 파라미터로 넘기는 편이 안전하다.

**④ for문 방식에서 `i + 1` 대신 `start + 1`을 넘기는 실수**

그러면 `[1,3]`을 만든 뒤 또 `[1,3]`을 만드는 식으로 중복이 생긴다. 재귀에는 **방금 고른 원소의 다음 위치(`i + 1`)**를 넘긴다.

## 한 줄 정리

> Subsets는 "넣기/안 넣기" 결정 트리를 DFS로 도는 백트래킹이다. **저장할 땐 복사(`new ArrayList<>(arr)`), 되돌릴 땐 마지막 인덱스 삭제(`remove(size - 1)`)**를 세트로 기억하고, 조합·순열로 확장하려면 `start` 인덱스를 쓰는 for문 템플릿을 쓴다.
