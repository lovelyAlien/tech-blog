# Find First and Last Position: lowerBound/upperBound로 경계 이분 탐색하기

정렬된 배열에서 target이 있는 범위(시작~끝 인덱스)를 O(log n)에 구하는 문제다. "값을 찾는" 일반적인 이분 탐색과 달리 "경계를 찾는" 이분 탐색 패턴(lowerBound/upperBound)이 필요해서, 이 패턴 자체를 정리해 둔다.

- 문제: [LeetCode 34. Find First and Last Position of Element in Sorted Array](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/)

## 문제 요약

- 정렬된 정수 배열 `nums`와 `target`이 주어진다.
- `target`이 등장하는 구간의 시작/끝 인덱스를 `[start, end]`로 반환한다.
- `target`이 없으면 `[-1, -1]`.
- 요구 조건: O(log n) — 단순히 값을 찾은 뒤 좌우로 스캔하면 값이 배열 전체를 채우고 있는 경우(예: `[5,5,5,5,5]`) 최악 O(n)이 되어 조건을 못 채운다.

```
Input:  nums = [5,7,7,8,8,10], target = 8
Output: [3,4]
```

## 접근: "값 찾기"가 아니라 "경계 찾기"

일반 이분 탐색은 `nums[mid] == target`을 만나면 바로 끝낸다. 이 문제는 거기서 멈추지 않고 **"target이 시작하는 위치"**와 **"target이 끝나는 위치"**를 각각 별도의 이분 탐색으로 구해야 O(log n)을 유지할 수 있다. 이때 쓰는 게 `lowerBound`/`upperBound` 패턴이다.

## lowerBound: target 이상인 값이 처음 나오는 위치

```java
private int lowerBound(int[] nums, int target) {
    int left = 0, right = nums.length - 1;   // 닫힌 구간
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) {
            left = mid + 1;
        } else {
            right = mid - 1;                  // mid를 답 후보에서 배제하되, "확정된 경계"는 유지
        }
    }
    return left;   // 루프 종료 시 left가 곧 답
}
```

## upperBound: target 초과인 값이 처음 나오는 위치

`lowerBound`와 부등호 하나만 다르다.

```java
private int upperBound(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] <= target) {     // lowerBound는 nums[mid] < target 이었음
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }
    return left;
}
```

| | lowerBound | upperBound |
|---|---|---|
| 찾는 것 | target **이상**(`>=`)인 첫 위치 | target **초과**(`>`)인 첫 위치 |
| 왼쪽으로 미는 조건 | `nums[mid] < target` | `nums[mid] <= target` |
| target 자신 포함 여부 | 포함 (target 위치를 가리킴) | 미포함 (target 다음을 가리킴) |

`[lowerBound(target), upperBound(target))` 구간이 정확히 target과 같은 값들의 범위가 된다.

## 왜 `return left`가 답인가 (invariant)

배열을 target 기준으로 O(target보다 작음)/X(target 이상)로 라벨링하면, 정렬되어 있으므로 항상 `OOOO...XXXX` 형태로 갈린다. 루프 도중 항상 다음이 유지된다.

- `left`보다 작은 모든 인덱스 → `nums[i] < target` (O 확정)
- `right`보다 큰 모든 인덱스 → `nums[i] >= target` (X 확정)

`nums[mid] < target`이면 mid까지 O로 확정되어 `left = mid + 1`로 O구역이 넓어지고, 반대면 mid까지 X로 확정되어 `right = mid - 1`로 X구역이 넓어진다. 루프가 끝나면(`left == right + 1`) 모름 구역이 사라지고 배열 전체가 `O구역[0, left-1]` + `X구역[left, n-1]`로 완전히 갈린다. 즉 `left`가 O구역 바로 다음 칸 = X구역의 시작 = target 이상인 값이 처음 나오는 위치다.

### 손으로 추적 (`nums = [1,3,5,5,5,8,9]`, `target=5`)

```
index: 0  1  2  3  4  5  6
value: 1  3  5  5  5  8  9
label: O  O  X  X  X  X  X   (O = <5, X = >=5)
```

| left | right | mid | nums[mid] | 판단 | 갱신 |
|---|---|---|---|---|---|
| 0 | 6 | 3 | 5 | `5<5`? 아니오 | `right=2` |
| 0 | 2 | 1 | 3 | `3<5`? 예 | `left=2` |
| 2 | 2 | 2 | 5 | `5<5`? 아니오 | `right=1` |
| 2 | 1 | - | - | 종료 | - |

`left=2` 반환 → 실제로 5가 시작하는 인덱스와 일치. `nums[0..1]`은 O, `nums[2..6]`은 X로 빈틈없이 갈렸다.

### 극단적인 경우

- target이 전부보다 작음 → 전부 X → `left = 0`
- target이 전부보다 큼 → 전부 O → `left = nums.length` (배열 밖, 삽입 위치를 뜻함)

`right`는 인덱스라서 `nums.length`를 표현 못 하지만 `left`는 그 제약이 없어서, target이 배열 끝을 넘어가는 경우도 자연스럽게 처리된다.

## 제출한 풀이

```java
class Solution {
    public int lowerBound(int[] nums, int target) {
        int left = 0;
        int right = nums.length-1; // 닫힌 구간
        while(left <=right) {
            int mid = left + (right - left)/2;

            if(nums[mid] < target) {
                left = mid + 1;
            } else { // nums[mid] >= target
                right = mid - 1;
            }
        }

        return left;
    }
    public int[] searchRange(int[] nums, int target) {

        int start = lowerBound(nums, target);
        if(start == nums.length || nums[start] != target) {
            return new int[]{-1, -1};
        }
        int end = lowerBound(nums, target+1) -1;

        return new int[]{start, end};
    }
}
```

`lowerBound(nums, target+1)`을 쓰면 `upperBound` 함수를 따로 안 만들어도 된다 (정수 배열에서 "target보다 큰 첫 값"과 "target+1 이상인 첫 값"은 동치). 다만 이 트릭은 정수형처럼 "다음 값"이 명확한 자료형에서만 성립하고, double 같은 실수 배열에는 못 쓴다.

처음엔 범위 체크(`start == nums.length || nums[start] != target`) 없이 바로 `nums[start] == target && nums[end] == target`으로 검사했다가 `target`이 모든 원소보다 큰 경우 `ArrayIndexOutOfBoundsException`이 나는 버그가 있었다 (아래 "흔한 버그" 참고). `start`가 유효하고 `nums[start] == target`임을 먼저 확정하면, `end`는 target이 최소 하나 존재함이 보장되므로 별도 검증 없이 안전하다.

## 흔한 버그: 배열 범위 체크 누락

`lowerBound`는 target이 배열에 있든 없든 **항상 인덱스를 반환**한다 (없으면 삽입 위치, 최대 `nums.length`까지). 그래서 반환값을 바로 `nums[idx]`에 인덱싱하면 범위를 벗어날 수 있다.

```java
// 버그 버전 — target이 모든 원소보다 크면 크래시
int start = lowerBound(nums, target);
int end = lowerBound(nums, target + 1) - 1;
if (nums[start] == target && nums[end] == target) return new int[]{start, end};
```

`nums = [1,2,3]`, `target = 5`면 `lowerBound`가 `nums.length(=3)`을 반환하는데, `nums[3]`에 바로 접근해 `ArrayIndexOutOfBoundsException`이 터진다. 빈 배열(`nums = []`)도 같은 문제. 반드시 `left == nums.length` 체크를 배열 인덱싱보다 먼저, `||`의 단축 평가로 안전하게 처리해야 한다.

```java
if (left == nums.length || nums[left] != target) {
    return new int[]{-1, -1};
}
```

## 다른 구현: 하나의 이분 탐색 함수로 좌/우 모두 처리

`isSearchingLeft` 플래그로 분기하는 방식도 있다. target을 찾아도 탐색을 끝내지 않고 계속 좁혀나가는 게 핵심이다.

```java
private int binarySearch(int[] nums, int target, boolean isSearchingLeft) {
    int left = 0, right = nums.length - 1;
    int idx = -1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > target) {
            right = mid - 1;
        } else if (nums[mid] < target) {
            left = mid + 1;
        } else {
            idx = mid;                          // 일치! 일단 기록
            if (isSearchingLeft) right = mid - 1;  // 더 왼쪽에 있는지 계속 탐색
            else left = mid + 1;                   // 더 오른쪽에 있는지 계속 탐색
        }
    }
    return idx;
}
```

`nums[mid] == target`을 만나도 `idx`에 기록만 해두고 원하는 방향으로 계속 좁히다가, 루프가 끝나는 순간 `idx`에는 마지막으로 찾은(=가장 왼쪽 또는 가장 오른쪽) target의 인덱스가 남는다. `lowerBound`/`upperBound` 두 함수로 나누는 방식보다 구현체는 하나지만, 조건 분기가 3갈래(`>`,`<`,`==`)라 `lowerBound` 방식보다 약간 덜 단순하다.

## 한 줄 정리
> lowerBound는 "target 이상인 첫 위치", upperBound는 "target 초과인 첫 위치" — 배열을 O(target보다 작음)/X(조건 만족)로 나눠보면 두 포인터가 만나는 지점(`left`)이 항상 그 경계이고, 이 두 경계 사이가 target이 존재하는 전체 구간이다.
