# Merge Intervals: 시작점 정렬 후 "끊길 때 확정"하기

겹치는 구간을 모두 합치는 문제다. 정렬 후 한 번 순회하는 구간 처리 패턴의 기본형이고, "언제 결과에 넣는가"에서 실수하기 쉬워서 정리해 둔다.

- 문제: [LeetCode 56. Merge Intervals](https://leetcode.com/problems/merge-intervals/)

## 문제 요약

- `intervals[i] = [start, end]` 배열에서 겹치는 구간을 모두 합쳐 반환한다.
- 끝점과 시작점이 같으면(`[1,4],[4,5]`) 겹친 것으로 본다.

```
Input:  [[1,3],[2,6],[8,10],[15,18]]
Output: [[1,6],[8,10],[15,18]]
```

## 접근: 시작점으로 정렬하면 겹칠 수 있는 구간이 이웃한다

정렬하지 않으면 한 구간이 누구와 겹치는지 알려고 나머지 전부와 비교해야 한다(O(n²)). **시작점 오름차순으로 정렬**하면 겹칠 수 있는 구간끼리 붙어 있게 된다. 그러면 "지금까지 합쳐 온 구간 `[start, end]`" 하나만 들고 왼쪽부터 순회하면 된다.

- `end < nextStart` → 끊김. 현재 구간을 **확정**하고 다음 구간으로 교체
- 그 외 → 겹침. `end`만 **늘린다**

## 제출한 풀이 (버그 있음)

처음 제출한 코드다. 정렬하고 한 번 순회하는 방향은 맞았지만, 결과에 넣는 시점이 틀렸다. 예제 1만 우연히 통과한다.

```java
class Solution {
    public int[][] merge(int[][] intervals) {
        // start 기준 정렬
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        int start = intervals[0][0];
        int end = intervals[0][1];
        int n = intervals.length;

        List<int[]> answer = new ArrayList<>();

        for(int i = 1 ; i < n ; i ++) {
            int nextStart = intervals[i][0];
            int nextEnd = intervals[i][1];
            if(end < nextStart) {
                answer.add(new int[]{nextStart, nextEnd});  // ❌ ① 현재 구간이 아니라 다음 구간을 넣음
                start = nextStart;
                end = nextEnd;
            } else {
                answer.add(new int[]{start, nextEnd});      // ❌ ② 겹칠 때마다 추가 → 중복
                end = nextEnd;                              // ❌ ③ max 없이 덮어씀
            }
        }
        // ❌ ④ 마지막 구간을 넣지 않음

        int m = answer.size();
        int[][] answerArr = new int[m][2];
        for(int i= 0 ; i < m ; i++) {
            answerArr[i][0] = answer.get(i)[0];
            answerArr[i][1] = answer.get(i)[1];
        }
        return answerArr;
    }
}
```

## 수정한 풀이

```java
class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        List<int[]> answer = new ArrayList<>();
        int start = intervals[0][0];
        int end = intervals[0][1];

        for (int i = 1; i < intervals.length; i++) {
            int nextStart = intervals[i][0];
            int nextEnd = intervals[i][1];

            if (end < nextStart) {                  // 끊김 → 현재 구간 확정 (①)
                answer.add(new int[]{start, end});
                start = nextStart;
                end = nextEnd;
            } else {                                // 겹침 → 늘리기만 (②)
                end = Math.max(end, nextEnd);       // (③)
            }
        }
        answer.add(new int[]{start, end});          // 마지막 구간 (④)

        return answer.toArray(new int[0][]);        // 복사 루프 대신 한 줄
    }
}
```

- 시간 O(n log n): 정렬 비용이 지배한다.
- 공간 O(n): 결과 리스트

## 핵심 포인트

### 1. 2차원 배열 정렬
```java
Arrays.sort(arr, (a, b) -> Integer.compare(a[k], b[k]));
```
`a`가 앞이면 오름차순, `b`가 앞이면 내림차순이다. `k`는 기준 칸 번호다. `a[0] - b[0]`는 값이 크면 오버플로가 날 수 있으니 `Integer.compare`를 쓴다.

### 2. `toArray(new int[0][])`
제네릭은 런타임에 타입 정보가 지워진다. 그래서 인자 없는 `toArray()`는 `Object[]`를 반환하고, 이걸 `int[][]`로 캐스팅하면 `ClassCastException`이 난다. 길이 0짜리 `int[][]`를 **타입 견본**으로 넘기면, 내부에서 `Arrays.copyOf(..., a.getClass())`로 알맞은 크기의 `int[][]`를 새로 만들어 준다. 이때 안쪽 `int[]`는 참조만 복사된다(얕은 복사).

## 주의할 점 / 흔한 실수

제출한 풀이의 버그 ①~④에 대한 반례다.

| 실수 | 반례 | 결과 |
|------|------|------|
| ① 끊길 때 **다음 구간**을 넣음 | `[[1,4],[5,6]]` | `[[5,6]]` (`[1,4]` 누락) |
| ② 겹칠 때마다 결과에 추가 | `[[1,3],[2,4],[3,5]]` | `[[1,4],[1,5]]` (중복) |
| ③ `end = nextEnd`로 덮어씀 | `[[1,10],[2,3]]` | `[[1,3]]` (정답은 `[[1,10]]`) |
| ④ 루프 뒤 마지막 구간 누락 | `[[1,4]]` | `[]` |

## 한 줄 정리
> 시작점으로 정렬하고, **끊길 때 이전 구간을 확정**하고, 겹치면 `max`로 늘리고, **루프가 끝나면 마지막 구간을 한 번 더 넣는다**.
