# Two Sum: 해시맵으로 O(n)에 짝 찾기

배열에서 "합이 target인 두 원소의 인덱스"를 찾는 문제다. 라이브 코딩테스트에서 자주 나오는 HashMap 유형의 기본기라, 풀이 흐름과 함정을 같이 정리해 둔다.

- 문제: [LeetCode 1. Two Sum](https://leetcode.com/problems/two-sum/)
- 제출: [내 제출 기록](https://leetcode.com/problems/two-sum/submissions/2148433291/)

## 문제 요약

- `nums` 배열과 `target`이 주어진다. 합이 `target`이 되는 **두 원소의 인덱스**를 반환한다.
- 정답은 정확히 하나 존재하고, 같은 원소를 두 번 쓸 수 없다. 반환 순서는 상관없다.
- 제약: `2 <= nums.length <= 10^4`, `-10^9 <= nums[i], target <= 10^9`
- Follow-up: O(n²)보다 빠르게 풀 수 있는가?

```
Input:  nums = [2,7,11,15], target = 9
Output: [0,1]     // nums[0] + nums[1] == 9
```

## 접근: 짝을 "찾는" 대신 "기억해 둔다"

이중 루프로 모든 쌍을 확인하면 O(n²)이다. 그런데 각 원소 `x`에 필요한 짝은 `target - x`로 이미 정해져 있다. 그 짝이 앞에서 나왔는지만 O(1)에 알 수 있으면 된다. 지나온 값을 HashMap(값 → 인덱스)에 저장해 두면 조회가 O(1)이 된다.

| 방식 | 시간 | 공간 | 비고 |
|---|---|---|---|
| 이중 루프 | O(n²) | O(1) | 가장 단순, n=10⁴라 통과는 하지만 follow-up 미충족 |
| 정렬 + 투포인터 | O(n log n) | O(n) | 인덱스가 섞여서 (값, 인덱스) 쌍을 따로 들고 가야 함 |
| **해시맵 한 번 순회** | **O(n)** | **O(n)** | 정답으로 권장 |

## 제출한 풀이

```java
import java.util.*;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> map = new HashMap<>();   // 값 -> 인덱스

        for (int i = 0; i < nums.length; i++) {
            int cur = nums[i];
            int other = target - cur;

            if (map.containsKey(other)) {
                return new int[]{map.get(other), i};
            }
            map.put(cur, i);
        }
        return null;
    }
}
```

## 핵심 포인트

### 1. 조회를 먼저 하고, 그다음에 put 한다

`put`을 먼저 하면 `nums[i]` 자기 자신이 짝으로 잡힌다. 예를 들어 `[3, 2]`, `target = 6`에서 3이 자기 자신과 짝지어진다. 조회 → put 순서를 지키면 "같은 원소를 두 번 쓰지 않는다"는 조건이 자연스럽게 지켜진다. `[3, 3]`, `target = 6`은 첫 번째 3이 맵에 들어간 뒤 두 번째 3에서 조회하므로 `[0, 1]`이 나온다.

### 2. 반환이 `{map.get(other), i}`인 이유

맵에는 **앞에서 지나온 원소**만 들어 있다. 그래서 `map.get(other)`는 항상 현재 `i`보다 작다. `{map.get(other), i}`로 쓰면 (작은 인덱스, 큰 인덱스) 순서가 되어 예제 출력 `[0, 1]`과 같다. 이중 루프 풀이에서는 `i < j`라 `{i, j}`로 쓰는 습관이 있어서 헷갈리기 쉬운데, 해시맵 풀이는 조회한 값이 앞선 인덱스라는 점이 다르다. 순서는 문제에서 상관없다고 했으니 `{i, map.get(other)}`도 정답 처리된다.

### 3. 손으로 추적하기 (라이브에서 꼭 하기)

`nums = [3, 2, 4]`, `target = 6`

```
i=0 cur=3 other=3  맵에 없음  → put(3,0)   맵: {3:0}
i=1 cur=2 other=4  맵에 없음  → put(2,1)   맵: {3:0, 2:1}
i=2 cur=4 other=2  맵에 있음(1) → return [1, 2]
```

## 다듬으면 좋은 점

- **조회가 두 번이다.** `containsKey`와 `get`이 각각 해시 조회다. 복잡도는 그대로 O(n)이지만 `Integer idx = map.get(other); if (idx != null)`로 한 번에 줄일 수 있다. 이때 `int`로 받으면 값이 없을 때 NPE가 나니 반드시 `Integer`로 받는다.
- **`return null`은 위험하다.** 이 문제는 해가 보장되어 도달하지 않지만, 라이브에서 "해가 없으면요?"라고 물을 수 있다. `throw new IllegalArgumentException("No solution")`이나 `return new int[0]`이 더 안전하다.
- **HackerRank는 `import java.util.*;`를 직접 써야 한다.** LeetCode는 자동으로 import해 주지만 다른 플랫폼은 그렇지 않다.
- **오버플로:** 값과 target이 ±10⁹이라 `target - cur`은 최대 2×10⁹이다. `int` 최대값(약 2.147×10⁹)보다 작아서 `int`로 충분하지만 여유가 크지 않다. 제약이 더 커지면 `long`으로 바꾼다.

## 한 줄 정리
> 짝은 `target - x`로 이미 정해져 있으니, 지나온 값을 HashMap에 넣어 두고 O(1)에 찾으면 O(n²)이 O(n)이 된다. 단, 조회를 먼저 하고 put은 나중에 한다.
