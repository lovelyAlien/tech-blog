# Validate Binary Search Tree: 반례로 이해하는 "범위를 들고 내려가는" DFS

이진 트리가 유효한 BST인지 판별하는 문제다. 부모와 자식만 비교하면 틀리는 게 핵심 함정이고, 반례 하나를 따라가다 보면 `validate(node.left, low, node.val) && validate(node.right, node.val, high)`라는 재귀 호출이 왜 그렇게 생겼는지 자연스럽게 나온다. 그 흐름을 정리해 둔다.

- 문제: [LeetCode 98. Validate Binary Search Tree](https://leetcode.com/problems/validate-binary-search-tree/)

## 문제 요약

- 왼쪽 서브트리의 **모든** 노드는 현재 노드보다 **작아야** 한다.
- 오른쪽 서브트리의 **모든** 노드는 현재 노드보다 **커야** 한다. 같은 값도 허용하지 않는다.
- 왼쪽과 오른쪽 서브트리도 각각 BST여야 한다.
- 노드 값 범위: `-2^31 <= Node.val <= 2^31 - 1`

```
Input:  root = [5,1,4,null,null,3,6]
Output: false   // 4가 루트 5의 오른쪽 자식인데 5보다 작다
```

## 접근: 부모 비교 → 반례 → 범위 전달

### 1단계: 가장 단순한 생각

처음 떠오르는 건 "왼쪽 자식은 나보다 작고, 오른쪽 자식은 나보다 크면 된다"는 조건이다.

```java
// ❌ 부모-자식만 비교
if (node.left != null && node.left.val >= node.val) return false;
if (node.right != null && node.right.val <= node.val) return false;
```

### 2단계: 반례로 깨뜨리기

```
      5
       \
        6
       /
      3      ← 부모 6보다 작으니 부모-자식 비교는 통과
```

3은 **루트 5의 오른쪽 서브트리**에 있으니 5보다 커야 한다. 그러니 이 트리는 BST가 아닌데, 1단계 코드는 `true`를 반환한다.

여기서 알 수 있는 것은 **3이 스스로를 검사하려면 부모(6)만 알아서는 부족하고, 조상(5)이 정한 조건까지 알아야 한다**는 점이다. 3 입장에서 필요한 정보는 이것이다.

> "나는 **5보다 크고**(5의 오른쪽에 있으므로) **6보다 작아야**(6의 왼쪽에 있으므로) 한다."

즉 필요한 건 **허용 범위 `(low, high)`** 이고, 이 범위는 조상에게서만 받을 수 있으니 **파라미터로 들고 내려가야** 한다.

### 3단계: 범위가 어떻게 좁혀지는지 따라가기

노드를 지날 때마다 범위의 한쪽 끝이 **현재 노드 값으로 바뀐다**.

```
              5   (-∞, +∞)
               \
                6   (5, +∞)      ← 5의 오른쪽: low가 5로 바뀜
               /
              3   (5, 6)         ← 6의 왼쪽: high가 6으로 바뀜
              ↑
         3 ∉ (5, 6) → false
```

- **왼쪽으로 내려갈 때** 왼쪽 자손은 전부 나보다 작아야 하니, **상한(high)이 내 값으로 바뀌고** 하한은 그대로 물려준다. → `(low, node.val)`
- **오른쪽으로 내려갈 때** 오른쪽 자손은 전부 나보다 커야 하니, **하한(low)이 내 값으로 바뀌고** 상한은 그대로 물려준다. → `(node.val, high)`

이걸 코드로 옮긴 것이 바로 이 줄이다.

```java
return validate(node.left, low, node.val)      // 왼쪽: 상한이 나로 바뀜
    && validate(node.right, node.val, high);   // 오른쪽: 하한이 나로 바뀜
```

"그대로 물려준다"는 부분이 핵심이다. 1단계 코드에 없던 게 바로 **조상이 정한 경계를 계속 전달하는 것**이다. 3이 5보다 커야 한다는 조건은 6을 거쳐 내려오는 동안 `low = 5`로 보존된다.

## 제출한 풀이

```java
class Solution {
    public boolean isValidBST(TreeNode root) {
        return validate(root, null, null);
    }

    private boolean validate(TreeNode node, Integer low, Integer high) {
        if (node == null) return true;

        if (low != null && node.val <= low) return false;
        if (high != null && node.val >= high) return false;

        return validate(node.left, low, node.val)
            && validate(node.right, node.val, high);
    }
}
```

## 핵심 포인트

### 1. 시그니처는 두 가지 질문으로 정해진다

현재 노드 하나에 서서 이렇게 묻는다.

| 질문 | 이 문제의 답 | 코드 |
|---|---|---|
| 조상에게서 무엇을 알아야 하나? | 허용 범위 (low, high) | 파라미터 `Integer low, Integer high` |
| 자식에게서 무엇을 받아야 하나? | 서브트리가 유효한지 여부 | 반환 타입 `boolean` |

이 문제처럼 조상의 정보를 파라미터로 들고 내려가는 패턴을 **Top-down DFS**라고 한다. 같은 패턴으로 푸는 문제로 112 Path Sum, 1448 Count Good Nodes가 있다.

### 2. 본문은 항상 3단 구조

1. **종료 조건**: `null`이면 `true`. 빈 트리는 유효한 BST다.
2. **현재 노드 검사**: 받은 범위 안에 내가 있는지 확인한다.
3. **자식에게 갱신된 범위를 넘기고 결과를 `&&`로 합친다.**

### 3. 복잡도

- 시간 O(n): 모든 노드를 한 번씩 방문한다.
- 공간 O(h): 재귀 스택 깊이가 트리 높이만큼이다. 균형 트리는 O(log n), 한쪽으로 치우친 트리는 O(n)이다.

## 주의할 점 / 흔한 실수

- **부모-자식만 비교하기**: 위 반례처럼 조상 조건을 놓친다. 가장 흔한 오답이다.
- **초기 범위를 `Integer.MIN_VALUE` / `MAX_VALUE`로 두기**: 노드 값 자체가 `2147483647`일 수 있어서 `[2147483647]` 입력이 `false`로 나온다. `null`로 "제한 없음"을 표현하거나 `long`과 `Long.MIN_VALUE` / `Long.MAX_VALUE`를 쓴다.
- **등호 처리**: 중복 값을 허용하지 않으므로 `<=`, `>=`로 비교해야 한다. `<`, `>`로 쓰면 `[2,2,2]`가 통과해 버린다.

## 한 줄 정리

> 각 노드는 부모가 아니라 **조상 전체가 정한 범위** 안에 있어야 한다. 그래서 범위를 파라미터로 들고 내려가되, 왼쪽으로 갈 때는 상한을, 오른쪽으로 갈 때는 하한을 내 값으로 바꾸고 나머지 한쪽은 그대로 물려준다.
