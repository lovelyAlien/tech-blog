# Daily Temperatures: Monotonic Stack으로 "다음으로 더 큰 값까지 거리" 구하기

각 날짜마다 "더 따뜻한 날이 오기까지 며칠 걸리는가"를 구하는 문제다. "다음으로 더 큰 원소(Next Greater Element)" 유형의 대표 문제이고, 모노토닉 스택(Monotonic Stack) 패턴의 기본기라 풀이 흐름과 최적화 포인트를 정리해 둔다.

- 문제: [LeetCode 739. Daily Temperatures](https://leetcode.com/problems/daily-temperatures/)

## 문제 요약

- `temperatures` 배열이 주어진다. 각 인덱스 `i`에 대해, `i`보다 뒤에 있으면서 `temperatures[i]`보다 큰 값이 처음 나오는 인덱스까지의 거리를 구해 `answer[i]`에 담는다.
- 그런 날이 없으면 `answer[i] = 0`.
- Follow-up: O(n²)보다 빠르게 풀 수 있는가?

```
Input:  temperatures = [73,74,75,71,69,72,76,73]
Output: [1,1,4,2,1,1,0,0]
```

## 접근: "아직 답을 못 찾은 날짜들"을 스택에 쌓아둔다

각 날짜마다 뒤쪽을 전부 훑으면 O(n²)이다. 핵심은, 아직 자기보다 따뜻한 날을 못 만난 날짜들을 스택에 쌓아두다가 더 따뜻한 날이 나오면 그 순간 한꺼번에 해소시키는 것이다. 스택에는 값이 아니라 **인덱스**를 저장한다 — 나중에 "며칠 후"를 구하려면 인덱스 차이가 필요하기 때문이다.

스택 안 인덱스가 가리키는 온도는 항상 아래에서 위로 갈수록 감소하는 상태(monotonic decreasing)를 유지한다. 새 온도가 스택 top의 온도보다 높으면 pop하면서 `현재 인덱스 - pop한 인덱스`로 답을 채우고, 이를 top이 더 이상 낮지 않을 때까지 반복한다.

| 방식 | 시간 | 공간 | 비고 |
|---|---|---|---|
| 이중 루프 (뒤쪽 전부 탐색) | O(n²) | O(1) | 가장 단순하지만 follow-up 미충족 |
| **Monotonic Stack (인덱스 저장)** | **O(n)** | **O(n)** | 정답으로 권장 |

## 제출한 풀이

```java
import java.util.*;

class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int[] answer = new int[temperatures.length];
        Deque<Integer> stack = new ArrayDeque<>();

        for (int i = 0; i < temperatures.length; i++) {
            while (!stack.isEmpty() && temperatures[stack.peek()] < temperatures[i]) {
                int top = stack.pop(); // 더 추웠던 날의 인덱스를 꺼냄
                answer[top] = i - top; // 기다린 일수(현재 날짜 - 추웠던 날짜)를 결과에 저장
            }
            stack.push(i);
        }
        return answer;
    }
}
```

## 핵심 포인트

### 1. 왜 O(n²)이 아니라 O(n)인가

겉보기엔 `for` 안에 `while`이 있어 이중 루프처럼 보이지만, 각 인덱스는 스택에 **최대 한 번 push, 최대 한 번 pop**된다. 전체 실행에서 push/pop 총합이 2n을 넘지 않으므로 amortized(분할 상환) O(n)이다. 면접에서 "이거 이중 루프 아닌가요?"라는 질문에 바로 이렇게 답할 수 있어야 한다.

### 2. 스택 불변조건(invariant)

스택은 항상 "아직 자기보다 따뜻한 날을 못 만난 인덱스들"만 들고 있고, 온도가 감소하는 순서(top이 가장 낮은 온도)로 유지된다. 이 불변조건 덕분에 `while` 조건 하나로 "다음 더 큰 값"을 정확히 찾아낼 수 있다.

### 3. 손으로 추적하기 (라이브에서 꼭 하기)

`temperatures = [73, 74, 75, 71, 69, 72]`

```
i=0 temp=73          스택 비어있음 → push(0)         스택: [0]
i=1 temp=74  74>73    pop(0), answer[0]=1-0=1 → push(1)   스택: [1]
i=2 temp=75  75>74    pop(1), answer[1]=2-1=1 → push(2)   스택: [2]
i=3 temp=71  71<75    push(3)                              스택: [2,3]
i=4 temp=69  69<71    push(4)                              스택: [2,3,4]
i=5 temp=72  72>69    pop(4), answer[4]=5-4=1
             72>71    pop(3), answer[3]=5-3=2
             72<75    push(5)                              스택: [2,5]
```

남은 스택(`[2,5]`)의 인덱스는 끝까지 더 따뜻한 날을 못 찾은 것이므로 `answer[2]=0`, `answer[5]=0`으로 초기값이 그대로 남는다.

## 다듬으면 좋은 점

- **`Deque<Integer>` → primitive `int[]` 스택.** `Deque<Integer>`는 push/pop마다 오토박싱·언박싱 비용이 든다. n이 크면(10^5 이상) 배열 기반 스택이 더 빠르고 GC 부담도 적다.
  ```java
  int[] stack = new int[temperatures.length];
  int top = -1; // stack pointer

  for (int i = 0; i < temperatures.length; i++) {
      while (top >= 0 && temperatures[stack[top]] < temperatures[i]) {
          int idx = stack[top--];
          answer[idx] = i - idx;
      }
      stack[++top] = i;
  }
  ```
  라이브 코테에서는 `Deque`로 먼저 정답을 낸 뒤, 시간이 남으면 이 최적화를 스스로 먼저 언급하는 게 좋은 인상을 준다.
- **변수명.** `stack.pop()`으로 꺼낸 값은 "스택의 top"이 아니라 "그 인덱스가 가리키는 날짜"이므로 `top`보다 `idx`/`prevIdx`가 의미상 더 명확하다.
- **엣지 케이스.** 빈 배열, 길이 1인 배열, 온도가 계속 내림차순이라 더 따뜻한 날이 아예 없는 경우 → `answer`가 전부 0으로 남는지 확인해 둔다.

## 한 줄 정리
> "아직 더 따뜻한 날을 못 찾은 인덱스"를 스택에 쌓아두고, 더 큰 값이 나올 때마다 pop하며 거리를 채우면 O(n²)이 O(n)이 된다 — 이게 모노토닉 스택 패턴이다.
