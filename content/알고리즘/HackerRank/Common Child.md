# Common Child — 최장 공통 부분 수열(LCS)을 2차원 DP로 푼다

두 문자열에서 글자를 지워 같은 문자열을 만들 때 그 최대 길이를 묻는 문제다. 이름만 다를 뿐 고전 DP인 **최장 공통 부분 수열(LCS, Longest Common Subsequence)** 그대로다. 핵심은 **`dp[i][j]`를 "앞 `i`글자와 앞 `j`글자"로 정의**하는 것이고, 그러면 한 칸이 왼쪽 위·위·왼쪽 세 칸만으로 정해진다.

- 문제: [HackerRank - Common Child](https://www.hackerrank.com/challenges/common-child/problem)

## 문제 요약

길이가 같은 두 대문자 문자열 `s1`, `s2`가 주어진다. 각 문자열에서 글자를 0개 이상 지워(남은 글자의 **순서는 유지**) 두 문자열을 같게 만들 때, 만들 수 있는 문자열의 **최대 길이**를 반환한다.

- 길이는 최대 5000.
- 지운 뒤 남은 글자는 연속하지 않아도 된다(부분 문자열이 아니라 **부분 수열**).

```
s1 = "HARRY", s2 = "SALLY" → 2   ("AY")
s1 = "SHINCHAN", s2 = "NOHARAAA" → 3   ("NHA")
```

## 접근 (핵심 아이디어)

- **브루트포스**: `s1`의 부분 수열을 전부 만들어 `s2`에 있는지 확인하면 부분 수열만 2^n개다. n = 5000이면 불가능.
- **관점 전환**: 두 문자열의 **마지막 글자**만 보고 판단할 수 있다.
  - 마지막 글자가 **같으면** 둘을 짝지어 공통 부분 수열 끝에 붙인다. 남은 문제는 두 글자를 뺀 앞부분.
  - **다르면** 둘 중 하나는 공통 부분 수열에 쓸 수 없다. `s1` 쪽 글자를 버리거나 `s2` 쪽 글자를 버리는 두 경우 중 나은 쪽.
- 이렇게 "앞부분"의 답을 재사용하는 구조라서, 앞부분 답을 표에 저장하는 DP로 O(n·m)에 풀린다.

## dp 배열의 정의

```
dp[i][j] = s1의 앞 i글자(s1[0..i-1])와 s2의 앞 j글자(s2[0..j-1])의
           최장 공통 부분 수열 길이
```

- **크기는 `(n+1) × (m+1)`.** 0번 행·열은 "빈 문자열"을 뜻한다. 한쪽이 빈 문자열이면 공통 부분 수열 길이는 0이라 `dp[0][*] = dp[*][0] = 0`이고, Java 배열은 0으로 초기화되니 따로 채울 필요가 없다.
- **인덱스가 하나씩 밀린다.** `dp[i][j]`의 "마지막 글자"는 `s1.charAt(i - 1)`, `s2.charAt(j - 1)`이다.
- **답은 `dp[n][m]`**: 두 문자열 전체에 대한 값.

### 점화식

```
s1[i-1] == s2[j-1]  →  dp[i][j] = dp[i-1][j-1] + 1          // 두 글자를 짝지어 붙임
s1[i-1] != s2[j-1]  →  dp[i][j] = max(dp[i-1][j],            // s1의 i번째 글자를 버림
                                     dp[i][j-1])             // s2의 j번째 글자를 버림
```

한 칸은 주변 세 칸만 본다.

```
dp[i-1][j-1]   dp[i-1][j]
dp[i][j-1]     dp[i][j]   ← 지금 채우는 칸
```

행은 위에서 아래로, 한 행 안에서는 왼쪽에서 오른쪽으로 채우면 이 세 칸은 항상 먼저 계산돼 있다.

## 이차배열 풀이

```java
public static int commonChild(String s1, String s2) {
    int n = s1.length(), m = s2.length();

    // dp[i][j] = s1의 앞 i글자와 s2의 앞 j글자의 최장 공통 부분 수열 길이
    // 0번 행과 0번 열은 "빈 문자열"이라 0으로 둔다 (Java 배열은 0으로 초기화됨)
    int[][] dp = new int[n + 1][m + 1];

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (s1.charAt(i - 1) == s2.charAt(j - 1)) {
                // 두 글자가 같으면 짝지어 붙인다: 두 글자를 빼기 전 상태 + 1
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                // 다르면 둘 중 하나는 못 쓴다: s1 글자를 버리거나, s2 글자를 버리거나
                dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }
    return dp[n][m];   // 두 문자열 전체에 대한 답
}
```

문제는 두 문자열 길이가 같다고 보장하지만, 길이 `n`, `m`을 따로 써서 길이가 달라도 그대로 동작하게 했다. 로컬에서 예제 4개(`HARRY/SALLY` 2, `AA/BB` 0, `SHINCHAN/NOHARAAA` 3, `ABCDEF/FBDAMN` 2)를 통과했고, 길이 5000 무작위 입력은 약 0.1초에 끝났다.

## 두 줄 배열 풀이

`dp[i][j]`를 채울 때 쓰는 칸은 `dp[i-1][j-1]`, `dp[i-1][j]`(**윗줄**)와 `dp[i][j-1]`(**현재 줄**)뿐이다. 그러니 표 전체를 들고 있을 필요 없이 `prev`(윗줄)와 `cur`(현재 줄) 두 배열만 번갈아 쓰면 된다.

```java
public static int commonChild(String s1, String s2) {
    char[] a = s1.toCharArray(), b = s2.toCharArray();   // charAt 반복 호출 대신 배열 접근
    int n = a.length, m = b.length;

    int[] prev = new int[m + 1];   // dp[i-1][*] : 윗줄
    int[] cur = new int[m + 1];    // dp[i][*]   : 지금 채우는 줄

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (a[i - 1] == b[j - 1]) {
                cur[j] = prev[j - 1] + 1;                // dp[i-1][j-1] + 1
            } else {
                cur[j] = Math.max(prev[j], cur[j - 1]);  // max(dp[i-1][j], dp[i][j-1])
            }
        }
        // 다 채운 cur가 다음 줄의 윗줄이 된다. 새 배열을 만들지 않고 참조만 맞바꾼다
        int[] tmp = prev;
        prev = cur;
        cur = tmp;
    }
    return prev[m];   // 마지막 줄을 채운 뒤 맞바꿨으므로 답은 prev에 있다
}
```

이차배열 풀이와 바뀐 곳은 인덱스뿐이다.

| 이차배열 | 두 줄 배열 |
|---|---|
| `dp[i-1][j-1]` | `prev[j-1]` |
| `dp[i-1][j]` | `prev[j]` |
| `dp[i][j-1]` | `cur[j-1]` |
| `dp[i][j]` | `cur[j]` |
| 답 `dp[n][m]` | 답 `prev[m]` (맞바꾼 뒤) |

- **`cur`를 매 줄마다 비우지 않아도 된다.** 맞바꾼 뒤 `cur`에는 두 줄 전 값이 남아 있지만, `j = 1..m`을 전부 덮어쓰고 `cur[0]`은 처음부터 끝까지 0이라 문제가 없다.
- **공간이 O(m)으로 준다.** `int` 5001개 두 줄이라 약 40KB. 이차배열의 약 100MB와 비교된다. 시간은 그대로 O(n·m).

이차배열 풀이와 무작위 입력 5000쌍(길이가 서로 다른 경우 포함)으로 비교해 결과가 모두 같았고, Java 힙을 32MB로 제한해도 길이 5000 입력이 약 0.05초에 끝났다.

## 핵심 포인트

### 손 추적 (`HARRY` / `SALLY`)

```
        ""  S  A  L  L  Y
   ""    0  0  0  0  0  0
   H     0  0  0  0  0  0
   A     0  0  1  1  1  1   ← (A, A) 같음: 왼쪽 위 0 + 1
   R     0  0  1  1  1  1   ← 전부 다름: 위나 왼쪽 값을 물려받음
   R     0  0  1  1  1  1
   Y     0  0  1  1  1  2   ← (Y, Y) 같음: 왼쪽 위 1 + 1
```

`dp[5][5] = 2`("AY").

### 같은 글자면 짝짓기만 보면 되는 이유

글자가 같을 때 "짝짓지 않는 경우"(`dp[i-1][j]`, `dp[i][j-1]`)와 비교하지 않아도 된다. 같은 글자를 짝짓지 않아서 더 길어지는 공통 부분 수열은 없기 때문이다. 짝짓지 않은 최적해가 있다면, 그 해의 마지막 짝을 이 두 글자로 바꿔도 길이가 줄지 않는다.

### 동일 길이 조건은 편의일 뿐

점화식은 두 문자열의 길이를 비교하지 않는다. 길이가 다르면 표 크기만 `(n+1) × (m+1)`, 답만 `dp[n][m]`이 된다. 같은 길이라는 조건은 변수를 `n` 하나로 줄여 주는 정도의 편의다.

### 복잡도

| | 값 |
|---|---|
| 시간 | O(n·m) → 5000 × 5000 = 2,500만 번 |
| 공간 | O(n·m) → `int` 약 2,500만 개 ≈ **100MB** |

시간은 충분하지만 메모리가 크다. 위의 **두 줄 배열 풀이**로 바꾸면 공간이 O(m)으로 준다. 짧은 문자열을 안쪽 반복문(`m`)에 두면 O(min(n, m)).

## 주의할 점 / 흔한 실수

- **인덱스 밀림** → `dp[i][j]`를 채울 때 `s1.charAt(i)`로 비교하면 한 칸씩 어긋나고 마지막에 범위를 벗어난다. 문자열은 `i - 1`, `j - 1`.
- **부분 문자열과 혼동** → 연속해야 하는 "최장 공통 부분 문자열"은 다를 때 0으로 리셋한다. 이 문제는 부분 수열이라 **위·왼쪽 중 큰 값을 물려받는다.**
- **길이 가정** → 길이가 같다고 `n` 하나로 짜면, 길이가 다른 입력에서 범위 초과나 오답이 난다. 이 문제는 괜찮지만 면접에서는 일반화를 한마디 덧붙인다.
- **메모리** → `int[5001][5001]`은 약 100MB. 제한이 빡빡하면 두 줄 배열로 줄인다.
- **두 줄 배열에서 답 위치** → 줄마다 맞바꾸고 끝나므로 답은 `cur[m]`이 아니라 **`prev[m]`**.
- **두 줄 배열 크기** → 안쪽 반복문이 도는 문자열 길이 + 1(`m + 1`)로 잡는다. `n + 1`로 잡으면 길이가 다를 때 범위를 벗어난다.

## 한 줄 정리
> `dp[i][j]` = **앞 `i`글자와 앞 `j`글자의 LCS 길이.** 글자가 같으면 **왼쪽 위 + 1**, 다르면 **위와 왼쪽 중 큰 값**, 답은 `dp[n][m]`. 윗줄만 쓰니 **두 줄 배열**로 공간을 O(m)까지 줄일 수 있다.
