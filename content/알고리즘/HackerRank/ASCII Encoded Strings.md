# ASCII Encoded Strings — 뒤집고, 첫 자리 숫자로 자릿수를 정해 끊어 읽는다

숫자 문자열을 뒤집은 뒤 **2자리 또는 3자리씩 끊어** ASCII 문자로 바꾸는 문제다. 핵심은 "몇 자리로 끊을지"를 정하는 기준인데, 유효한 값의 범위 덕분에 **첫 자리 숫자만 보면** 자릿수가 하나로 정해진다. HackerRank 공개 문제가 아니라 기업 온라인 코딩테스트(Goldman Sachs, Salesforce 등)에서 공유된 유형이라 로컬 문제 틀을 만들어 풀었다.

- 문제 설명 출처: [jzleetcode - HackerRank ASCII Encoded Strings](https://jzleetcode.github.io/posts/leet-0091-hackerrank-ascii-encoded-strings/)

## 문제 요약

원래 문자열의 각 문자를 ASCII 숫자로 바꿔 이어 붙이고, 그 숫자 문자열 전체를 **뒤집은** 것이 입력으로 주어진다. 원래 문자열을 복원해 반환한다.

- 원래 문자열에는 대문자(65~90), 소문자(97~122), 공백(32)만 나온다.
- 원래 문자열 길이는 최대 10^5.

```
"HackerRank" → 72 97 99 107 101 114 82 97 110 107
             → "7297991071011148297110107"
             → 뒤집기 → "7010117928411101701997927"   (이게 입력)

decode("7010117928411101701997927") → "HackerRank"
```

## 접근 (핵심 아이디어)

1. **뒤집기**: 인코딩 마지막 단계가 뒤집기였으니, 다시 뒤집으면 원래 순서의 ASCII 숫자열이 된다.
2. **끊어 읽기**: 숫자 사이에 구분자가 없어서 몇 자리씩 읽을지 정해야 한다. 유효한 값을 첫 자리로 나눠 보면 겹치는 게 없다.

| 첫 자리 | 가능한 값 | 자릿수 |
|---|---|---|
| `3` | 32 (공백) | 2 |
| `6` ~ `9` | 65~90, 97~99 | 2 |
| `1` | 100~122 | 3 |

첫 자리가 정해지면 자릿수도 하나로 정해지니 **앞에서부터 한 번 훑으면** 된다. 되돌아가거나 경우를 나눠 탐색할 필요가 없다.

## 제출한 풀이

```java
public static String decode(String encoded) {
    String step1 = new StringBuilder(encoded).reverse().toString();
    StringBuilder result = new StringBuilder();
    for (int i = 0; i < step1.length(); ) {
        int ascii;
        if (step1.charAt(i) == '3') {
            ascii = 32;  // 공백
            i += 2;      // 32는 두 자리 숫자
        } else if (step1.charAt(i) == '6' || step1.charAt(i) == '7' || step1.charAt(i) == '8' || step1.charAt(i) == '9') {
            ascii = Integer.parseInt(step1.substring(i, i + 2));
            i += 2;      // 65~90, 97~122는 두 자리 숫자
        } else {
            ascii = Integer.parseInt(step1.substring(i, i + 3));
            i += 3;      // 나머지는 세 자리 숫자
        }
        result.append((char) ascii);
    }
    return result.toString();
}
```

로컬 테스트 9개(예제, 한 문자, 공백만, `0`으로 시작하는 입력, 2·3자리 혼합 등)를 모두 통과했다. 무작위 문자열 2만 개를 인코딩해 넣었을 때도 전부 원래대로 복원됐고, 길이 10^5 입력도 즉시 끝났다.

## 핵심 포인트

### 첫 자리 숫자로 자릿수가 하나로 정해진다

위 표처럼 첫 자리 `1`은 3자리 값에만, `3`·`6`~`9`는 2자리 값에만 나온다. 그래서 탐욕적으로 앞에서부터 끊어도 **다른 해석이 생길 여지가 없다.** (LeetCode 91 Decode Ways처럼 여러 해석이 가능한 문제였다면 DP가 필요했을 것이다.)

### 손 추적 (예제 일부)

```
입력      "23511011501782351112179911801562340161171141148"
뒤집기    "84114117116104326510811997121115328710511011532"

i=0  '8' → 2자리 "84"  → 'T'
i=2  '1' → 3자리 "114" → 'r'
i=5  '1' → 3자리 "117" → 'u'
i=8  '1' → 3자리 "116" → 't'
i=11 '1' → 3자리 "104" → 'h'
i=14 '3' → 2자리 "32"  → ' '
...                       → "Truth Always Wins "
```

### 복잡도

| 단계 | 비용 |
|---|---|
| 뒤집기 | O(n) |
| 끊어 읽기 | 각 자리를 한 번씩 → O(n) |
| **합계** | **시간 O(n), 공간 O(n)** (n = 인코딩된 문자열 길이) |

## 주의할 점 / 흔한 실수

- **뒤집기를 빼먹음** → 뒤집지 않으면 `"70"`, `"10"` 같은 값이 나와 전혀 다른 문자가 된다.
- **`0`으로 시작하는 입력** → `"001"`을 뒤집으면 `"100"`('d')이다. 입력을 숫자(`int`/`long`)로 먼저 바꾸면 앞자리 0이 사라지고, 길이 10^5면 범위도 넘는다. **문자열 그대로** 다룬다.
- **주석의 범위 표기** → 제출 코드의 `// 65~90, 97~122는 두 자리 숫자`는 정확하지 않다. 97~99만 2자리이고 100~122는 `1`로 시작하는 3자리라 `else` 분기로 간다. 코드는 맞게 동작하지만 면접에서 말로 설명할 때는 범위를 정확히 짚는다.
- **잘못된 입력** → 끝에 숫자가 모자라면 `substring`에서 `StringIndexOutOfBoundsException`이 난다. 문제는 유효한 입력만 준다고 가정하지만, 면접에서는 이 가정을 먼저 확인한다.
- **`String`에 `+`로 이어 붙이기** → 길이 10^5에서 O(n²)이 될 수 있다. `StringBuilder`를 쓴다.

## 한 줄 정리
> 숫자열을 **뒤집고**, 첫 자리가 `1`이면 3자리, 아니면 2자리로 **끊어 `(char)`로 바꾼다.** 유효한 값의 범위가 겹치지 않아서 한 번 훑으면 O(n)에 끝난다.
